先認識主角：LLM

LLM（大型語言模型）：像 ChatGPT、Claude 這種「讀文字、寫文字」的 AI。

一般聊天
你問一句，它答一句，就結束。
AI Agent
拿到一個目標後，自己反覆「想→做→看結果」，直到完成。

出處：wiki/concepts/什麼是AI-Agent

生活比喻

聊天機器人
像問路時回答你的路人：說完就結束。
AI Agent
像幫你訂好機票、查好天氣、再把行程寄給你的助理。

出處：wiki/concepts/什麼是AI-Agent

一句話定義

AI Agent ＝ 會自己決定下一步、會用工具、會看結果再修正的 LLM 程式。

“They are typically just LLMs using tools based on environmental feedback in a loop.” — Anthropic, Building effective agents

翻譯：Agent 通常就是「在迴圈中，根據環境回饋使用工具的 LLM」。

出處：wiki/concepts/什麼是AI-Agent ← S1

核心機制①：Agent 迴圈

1 蒐集資訊→2 採取行動→3 檢查結果↺4 重複
“gather context -> take action -> verify work -> repeat” — Claude Agent SDK

比喻：像學生寫作業——查資料、寫、對答案、改錯，再繼續。

出處：wiki/concepts/Agent迴圈 ← S5、S1

核心機制②：工具（Tools）

工具是 Agent 能「動手」的方法：搜尋網路、查天氣、執行程式、讀寫檔案。

沒有工具的 LLM 只能「說」；有了工具，它才能真的「做」。給它一台電腦（終端機），就等於給了一整套工具。

工具很多時，要用名稱前綴分組（namespacing），避免 Agent 選錯工具。

出處：wiki/concepts/工具Tools ← S3、S5

Workflow 和 Agent 不一樣

Workflow（工作流程）Agent（代理）
誰決定步驟工程師事先寫好LLM 執行時自己決定
適合步驟固定、可預測的任務步驟無法事先預測的開放任務
缺點不夠彈性成本高、較難預測

出處：wiki/concepts/Workflow與Agent的差別 ← S1

五種常見的 Workflow 模式

Prompt chaining 串接
一步接一步，像流水線
Routing 分流
先分類再處理，像客服總機
Parallelization 平行
同時做多件事再合併
Orchestrator-workers
指揮者拆任務、分派給工人
Evaluator-optimizer
一個寫、一個評，反覆修改

進階①：上下文是有限的

上下文（context）＝ LLM 一次能「看到」的所有文字。token 是 LLM 計算文字量的單位（大約一個字或半個英文單字）。

塞太多，模型反而會分心。原則是放「最少但最有用」的資訊，其他的只記住「去哪裡找」，需要時再查。

“…must be treated as a finite resource…” “…the smallest possible set of high-signal tokens…”

出處：wiki/concepts/上下文工程 ← S4

進階②：多代理系統

一個「主 Agent」拆解問題，派好幾個「子 Agent」平行調查，最後彙整。

效果
在 Anthropic 內部研究評測中，比單一 Agent 好 90.2%
代價
使用的 token 約是一般聊天的 15×

出處：wiki/concepts/多代理系統 ← S2

進階③：做很久的任務

任務太長時，下一輪的 Agent 會「忘記」前面做過什麼，還可能看到一點進度就以為做完了。

  • 先由初始化 agent 準備好環境與進度檔
  • 之後每次只做一小步並留下紀錄，下一輪看紀錄接著做

出處：wiki/concepts/長時間任務 ← S6

什麼時候「不該」用 Agent？

“we recommend finding the simplest solution possible, and only increasing complexity when needed”

Agent 比較貴、比較慢、也比較難預測。如果步驟是固定的，用一般程式或 Workflow 就好；只有在步驟無法事先規劃時，才值得用 Agent。

出處：wiki/concepts/Workflow與Agent的差別 ← S1

小測驗（點開看答案）

1. Agent 和一般聊天 AI 最大的差別？Agent 會在迴圈中自己決定下一步、使用工具，並根據結果修正。
2. Agent 迴圈的四個步驟？蒐集資訊 → 採取行動 → 檢查結果 → 重複。
3. 步驟固定的任務該用 Agent 嗎？通常不用。先找最簡單的解法，Workflow 或一般程式就夠了。

總結＋資料來源

  • Agent ＝ LLM ＋ 工具 ＋ 迴圈（看結果再修正）
  • Workflow 是寫死的流程；Agent 是 LLM 自己決定流程
  • 上下文有限、多代理很耗 token、長任務要留紀錄
  • 能簡單就簡單
