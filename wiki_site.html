wiki/Agent迴圈.md

Agent 迴圈（Agent Loop）

Agent 的核心是一個重複的迴圈：

• 蒐集資訊（gather context）

• 採取行動（take action，例如呼叫工具）

• 檢查結果（verify work）

• 重複，直到完成

• gather context -> take action -> verify work -> repeat S5

• environmental feedback in a loop S1：每一輪都根據「環境回饋」（工具結果、錯誤訊息）調整。

比喻： 像學生寫作業：查資料→寫→對答案→改錯，再繼續。

延伸：工具Tools、長時間任務

wiki/Workflow與Agent的差別.md

Workflow 與 Agent 的差別

Workflow（工作流程）Agent（代理）
誰決定步驟工程師事先寫好LLM 執行時自己決定
適合步驟固定、可預測的任務步驟無法事先預測的開放任務
缺點不夠彈性成本高、較難預測

• Workflows are systems where LLMs and tools are orchestrated through predefined code paths. S1

• 不一定要用 agent：we recommend finding the simplest solution possible, and only increasing complexity when needed S1

延伸：五種Workflow模式、什麼是AI-Agent

wiki/上下文工程.md

上下文工程（Context Engineering）

上下文（context）＝ LLM 一次能「看到」的所有文字，包含指令、對話、工具結果。

• 它是有限的：Context, therefore, must be treated as a finite resource with diminishing marginal returns. S4

• 原則：只放最需要的：finding the smallest possible set of high-signal tokens S4

• 技巧：只記住「去哪裡找」，需要時再查：maintain lightweight identifiers (file paths, stored queries, web links, etc.) S4

延伸：長時間任務、多代理系統

wiki/五種Workflow模式.md

五種 Workflow 模式（S1）

• Prompt chaining（串接）：一步接一步，上一步輸出是下一步輸入。像工廠流水線。

• Routing（分流）：先分類，再交給專門處理的流程。像客服總機。

• Parallelization（平行）：同時做多件事再合併。

• Orchestrator-workers（指揮者＋工人）：一個 LLM 拆任務、分派給其他 LLM。多代理系統就是這種。

• Evaluator-optimizer（評審＋改進）：一個寫、一個評，反覆修改。

• Building block: The augmented LLM S1——以上都建立在「LLM＋檢索＋工具＋記憶」這個積木上。

延伸：Workflow與Agent的差別

wiki/什麼是AI-Agent.md

什麼是 AI Agent？

一句話： AI Agent 就是「會自己決定下一步、會用工具、會看結果再修正」的 LLM 程式。

• LLM（大型語言模型）：像 ChatGPT、Claude 這種「讀文字、寫文字」的 AI。

• 一般聊天：你問一句，它答一句，就結束。

• Agent：拿到一個目標後，自己反覆「想→做→看結果」，直到完成。

• They are typically just LLMs using tools based on environmental feedback in a loop. S1

• are systems where LLMs dynamically direct their own processes and tool usage S1

生活比喻： 聊天機器人像「問路時回答你的路人」；Agent 像「幫你訂好機票、查好天氣、再把行程寄給你的助理」。

延伸：Workflow與Agent的差別、Agent迴圈、工具Tools

wiki/多代理系統.md

多代理系統（Multi-agent）

多個 agent 分工合作：一個「主 agent」拆解問題，派「子 agent」平行調查。

• uses a multi-agent architecture with an orchestrator-worker pattern S2

• 效果：outperformed single-agent Claude Opus 4 by 90.2% on our internal research eval S2

• 代價：multi-agent systems use about 15× more tokens than chats S2

延伸：五種Workflow模式、上下文工程

wiki/工具Tools.md

工具（Tools）

工具是 agent 能「動手」的方法，例如搜尋網路、查天氣、執行程式、讀寫檔案。

• 工具是給 agent 用的新型軟體：Tools are a new kind of software which reflects a contract between deterministic systems and non-deterministic agents. S3

• 給 agent 一台電腦，就等於給它一整套工具：by giving Claude access to the user’s computer (via the terminal) S5

• 工具很多時，用名稱前綴分組（namespacing）避免選錯：Namespacing (grouping related tools under common prefixes) S3

延伸：Agent迴圈

wiki/長時間任務.md

長時間任務的挑戰

任務做很久時，對話會超過上下文上限，下一次「醒來」的 agent 不記得之前做過什麼。

• 對策一：第一次先由「初始化 agent」準備環境：an initializer agent that sets up the environment on the first run S6

• 常見錯誤：看到有些進度就以為做完：see that progress had been made, and declare the job done S6

• 對策二：每次只做一小步並留下紀錄：Every subsequent session asks the model to make incremental progress, then leave structured updates. S6

延伸：Agent迴圈、上下文工程

SCHEMA.md
# LLM Wiki 規則（SCHEMA）

主題：AI Agent 是什麼？——給完全沒接觸過的人
維護者：LLM（依本檔規則維護），人類負責選資料與審核

## 資料夾
- `raw/`：原始資料，只讀不改（S1–S6）
- `wiki/sources/`：每篇資料一頁摘要
- `wiki/concepts/`：概念頁，整合多篇資料
- `wiki/index.md`：所有頁面目錄；`wiki/log.md`：每次操作紀錄

## 寫作規則
1. 每個重要論點要附原文引用，格式：「英文原句片段」[S編號]，片段必須能在 raw/ 中逐字找到。
2. 頁面之間用 [[頁面名稱]] 互連，連結目標必須存在。
3. 第一次出現的專有名詞要用一句白話解釋。
4. 新資料 ingest 時：寫 source 頁 → 更新相關 concept 頁 → 更新 index → 寫 log。

## 三種操作
- ingest：讀一篇 raw → 更新 wiki
- query：從 wiki（不是 raw）回答問題或產生簡報
- lint：檢查引用是否存在、連結是否斷掉、是否有孤立頁面
